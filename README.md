# Построение кубического сплайна

Лабораторная работа, вариант 24. Натуральный кубический сплайн построен четырьмя способами: C + Pthreads, C + OpenMP, C + MPI и Python + MPI.

Трёхдиагональная система для вторых производных решается методом параллельной циклической редукции (PCR). Граничные условия: вторые производные на концах равны нулю.

## Состав проекта

| Путь | Содержимое |
|---|---|
| `src/spline.c` | Три реализации на C с отдельными ветвями Pthreads, OpenMP и MPI |
| `src/spline_mpi.py` | Python + MPI |
| `src/spline_math.py` | Численные функции Python |
| `intro/` | Вводная работа с JSON-матрицей |
| `tests/` | Тесты корректности |
| `scripts/` | Генерация данных, проверка и построение графиков |
| `slurm/` | Пакетные серии экспериментов |
| `results/` | Таблица измерений и графики |
| `logs/` | Исходные журналы экспериментов |
| `docs/report.pdf` | Отчёт |
| `docs/latex/` | Исходники отчёта и рисунки |
| `docs/VIDEO.md` | Порядок записи видео |

## Сборка на кластере

Рабочий каталог проекта на кластере: `~/spline-lab`.

```bash
module load compiler/gcc/11 mpi/openmpi/4.1.6/gcc/11 python/3.10
cd ~/spline-lab
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
make -j3
mkdir -p logs results work
```

Если окружение `.venv` уже создано с нужными библиотеками, достаточно активировать его. Скрипты Slurm используют именно `~/spline-lab/.venv`.

## Проверка корректности

На управляющем сервере запросить вычислительные ресурсы:

```bash
salloc -N1 -p cascade --ntasks=4 --cpus-per-task=1 --time=00:20:00
ssh "$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n 1)"
```

На вычислительном узле:

```bash
module load compiler/gcc/11 mpi/openmpi/4.1.6/gcc/11 python/3.10
source ~/spline-lab/.venv/bin/activate
cd ~/spline-lab
export OMPI_MCA_pml=ob1
export OMPI_MCA_btl=self,vader,tcp
export OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1
bash tests/correctness.sh
```

Ожидаемый итог: `ALL FOUR IMPLEMENTATIONS PASSED`. Проверяются две точки, константа, линейная функция, синус и неравномерная сетка, с 1, 2 и 4 исполнителями. Эталон: SciPy `CubicSpline(..., bc_type='natural')`.

После проверки выполнить `exit`, затем на управляющем сервере освободить текущее выделение командой `scancel "$SLURM_JOB_ID"` из оболочки salloc. Если срок выделения уже истёк, проверить фактическую очередь через `squeue -u "$USER"`.

## Эксперименты

Выполнять из каталога проекта на управляющем сервере:

```bash
sbatch slurm/threads.sbatch
sbatch slurm/mpi.sbatch
squeue -u "$USER"
```

Потоки: 1, 2, 4, 8, 12, 16, 24, 32, 48. MPI-процессы: 1, 2, 4, 8, 16, 28, 56, 84, 112. Размеры: 10 000, 100 000, 1 000 000 точек. Минимум пяти повторов.

Для потоков запрашивается один узел cascade; для MPI четыре узла tornado по 28 задач. У MPI явно задан транспорт self/vader/TCP. На каждой стадии массивы собираются через Allgatherv, поэтому расходы связи могут превышать выигрыш от параллелизма.

После завершения заданий:

```bash
source ~/spline-lab/.venv/bin/activate
python3 scripts/plot.py
```

`results/benchmark.csv` содержит время, ускорение и эффективность. База для ускорения выбирается отдельно для каждой реализации и размера. Таймер исключает файловый ввод-вывод и формирование системы; включает решение, коэффициенты и необходимые служебные расходы.

## Сохранённые результаты

Исходные серии 9261711 и 9261714 завершились 11-12 ноября 2026 года. В сохранённых журналах 108 конфигураций. Все четыре реализации прошли кластерные тесты. На миллионе точек лучший результат OpenMP: 0,0102605 с на 48 потоках, ускорение 13,646.

Новые задания получат другие номера. Текущие журналы и CSV не следует смешивать с новыми сериями при сравнении оборудования или условий. Отдельная оценка разброса требует сохранения времён каждого повтора.

## Формат файлов

Вход: количество узлов в первой строке, затем пары x y. Координаты конечные и строго возрастающие. Выход: по строке a b c d на интервал, для полинома `a + b*t + c*t^2 + d*t^3`, где `t = x - x_i`.

```bash
python3 scripts/generate.py work/demo.txt --n 129 --case uneven
./bin/spline_pthreads work/demo.txt 4 work/out.txt
python3 scripts/check.py work/demo.txt work/out.txt
```

Для MPI число процессов определяется `mpirun -np`; аргумент после входного файла сохранён для общего интерфейса четырёх программ.
